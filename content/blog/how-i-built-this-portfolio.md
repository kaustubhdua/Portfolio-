This portfolio is a Minecraft-style village by day and a Nether fortress by night. Scrolling walks a camera down the road, and each section of the page is a stop on it. There is no 3D library. Here is how the pieces fit together, and the decisions that mattered.

## The world is a grid of blocks

Each world is a single three-dimensional array of block ids, 64 by 44 by 216 blocks. Buildings, trees, bridges and the lava sea are all written as code that fills boxes in that array, with a seeded random generator so the world is identical on every visit. A house, for example, is a function: a base course, log corners, plank walls, panes, a door and a gabled roof of stairs.

Blocks come in two kinds. Full cubes are cheap. Shaped blocks such as stairs, slabs, fences and doors are lists of small boxes, so a fence grows arms toward its neighbours the way the game's fences do.

## Meshing: draw only what you can see

Drawing every block would be far too slow. The mesher walks the grid once and emits a quad only where a solid block touches air or a see-through block. Faces are packed into one vertex buffer per chunk, and lighting is baked into the vertices, so the fragment shader stays almost empty.

## A texture atlas made by a script

The textures are not Mojang's. Mojang's guidelines treat textures and sounds as protected brand assets, so every tile in the atlas is generated by a script in the repository, and the site says plainly that it is not affiliated with Mojang or Microsoft.

## Scroll is just a number

The camera path is a spline through seven stops, one per section. The page reports how far you have scrolled as a number from 0 to 6, and the renderer samples the spline at that number. Because the position is a pure function of scroll, going backwards works for free, and tab switches or clicks can nudge the camera or trigger a block change without any special cases.

## Staying fast on a phone

- The world loads after the page, so the text paints first and the 3D scene never blocks reading.
- An adaptive quality controller lowers the render resolution if frames run long, and raises it again only after a sustained good stretch, so it settles instead of flickering.
- Rendering pauses when the tab is hidden or the canvas is off screen.
- JavaScript has a size budget that the build checks, currently 160 kB gzipped.
- Without WebGL, or with reduced motion on, the site falls back to 2D scenes. Nothing depends on the 3D layer to be readable.

## Free roam

Explore mode hides all the text and lets you walk the world: pointer lock and WASD on a laptop, a touch joystick on a phone. Walking physics is a small pure function over the block grid, which made it easy to test without a browser. One bug taught me a lesson: some browsers send a huge fake mouse movement right after pointer lock starts, which spun the view into a wall, so the renderer now ignores deltas that are too large in the first moments.

## Tests

Plain-Node tests check the world and the quality controller, and Playwright tests drive the production build: layout at several widths, keyboard use, the portal, mining blocks and console errors.
